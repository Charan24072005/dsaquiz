🔁 Recursion

Recursion is a programming technique where a function calls itself to solve a problem. It breaks a big problem into smaller subproblems until a base condition is met.

Why Recursion is Important

  • Simplifies complex problems
  • Used in tree and graph traversal
  • Foundation for Divide and Conquer
  • Frequently asked in interviews

Key Components of Recursion

1. Base Case

The base case stops the recursion. Without a base case, recursion will continue infinitely and cause stack overflow.

2. Recursive Case

The recursive case calls the function with a smaller input, moving closer to the base case.

How Recursion Works (Call Stack)

Each recursive call is stored in the call stack. Once the base case is reached, the stack starts unwinding and returns results step by step.

Example Problems Using Recursion

  • Factorial of a number
  • Fibonacci series
  • Tree traversals (Inorder, Preorder, Postorder)
  • Binary Search

Time and Space Complexity

Time complexity depends on the number of recursive calls. Space complexity depends on recursion depth due to the call stack.

Recursive Algorithms – Code & Time Complexity Calculation

Recursive algorithms solve a problem by breaking it into smaller subproblems. Time complexity depends on how many recursive calls are made and how the recursion tree grows with input size n.

Algorithm & Code Explanation & Time Complexity
Factorial

fact(n) {
  if(n == 0) return 1;
  return n * fact(n-1);
} 		One recursive call is made for each value of n.
Recursion depth = n.
Each call does constant work.
Time Complexity: O(n)
Space Complexity: O(n) (call stack)
Fibonacci (Naive)

fib(n) {
  if(n <= 1) return n;
  return fib(n-1) + fib(n-2);
} 		Each function call makes two more recursive calls.
Number of calls grows exponentially.
Large amount of repeated computation occurs.
Time Complexity: O(2ⁿ)
Space Complexity: O(n)
Binary Search (Recursive)

binarySearch(arr, low, high, x) {
  if(low > high) return -1;
  mid = (low + high) / 2;
  if(arr[mid] == x) return mid;
  if(arr[mid] > x)
    return binarySearch(arr, low, mid-1, x);
  return binarySearch(arr, mid+1, high, x);
} 		Search space is divided into half at each step.
Number of recursive calls = log₂ n.
Each call performs constant work.
Time Complexity: O(log n)
Space Complexity: O(log n)
Sum of Array Elements

sum(arr, n) {
  if(n == 0) return 0;
  return arr[n-1] + sum(arr, n-1);
} 		Function is called once for each element.
Recursion depth equals array size.
Each call does constant work.
Time Complexity: O(n)
Space Complexity: O(n)
Tower of Hanoi

hanoi(n, A, B, C) {
  if(n == 1) return;
  hanoi(n-1, A, C, B);
  move disk from A to C;
  hanoi(n-1, B, A, C);
} 		Each call generates two more recursive calls.
Total number of moves = 2ⁿ − 1.
Recursion tree grows exponentially.
Time Complexity: O(2ⁿ)
Space Complexity: O(n)

Recursive time complexity is determined by the number of recursive calls and how the problem size changes at each step.

Advantages of Recursion

  • Clean and readable code
  • Natural fit for hierarchical data
  • Easy implementation of divide-and-conquer algorithms

Disadvantages of Recursion

  • Uses extra memory due to call stack
  • May cause stack overflow
  • Slower than iterative solutions in some cases

Common Mistakes Students Make

  • Missing or incorrect base case
  • Not reducing the problem size
  • Confusing recursion with iteration
  • Ignoring stack space usage

Recursion in Interviews

Interviewers check your understanding of base cases, recursion depth, and time complexity. Always explain how recursion terminates.
