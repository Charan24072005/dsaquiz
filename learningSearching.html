🔍 Searching Algorithms

Searching is the process of finding a specific element within a data structure. Efficient searching reduces time complexity and improves application performance.

Why Searching is Important

  • Quickly locate data
  • Improve algorithm efficiency
  • Foundation for databases and indexing
  • Frequently asked in interviews

Linear Search

Linear Search is the simplest searching technique. It scans each element of the list sequentially from the beginning until the target element is found or the entire list has been checked. Since it does not rely on any order, it can be used on both sorted and unsorted data structures, but it becomes inefficient for large datasets.

  • Best Case: O(1)
  • Average Case: O(n)
  • Worst Case: O(n)
  • Works on both sorted and unsorted data

Binary Search

Binary Search is an efficient searching algorithm that works only on sorted arrays. It compares the target value with the middle element of the array and eliminates half of the remaining elements in each step. This repeated halving of the search space makes Binary Search much faster than Linear Search for large datasets.

  • Best Case: O(1)
  • Average Case: O(log n)
  • Worst Case: O(log n)
  • Requires sorted data

Jump Search(Optional For reference)

Jump Search moves ahead by fixed steps and then performs linear search within the block.

  • Best Case: O(1)
  • Average Case: O(√n)
  • Worst Case: O(√n)
  • Requires sorted array

Interpolation Search(Optional For reference)

Interpolation Search estimates the position of the target based on its value.

  • Best Case: O(1)
  • Average Case: O(log log n)
  • Worst Case: O(n)
  • Works best for uniformly distributed data

Searching Algorithms – Code & Time Complexity Calculation

Searching algorithms locate a target element in a data structure. Time complexity depends on how many comparisons the CPU performs as the input size n increases.

Algorithm & Code Explanation & Time Complexity
Linear Search

for(int i = 0; i < n; i++) {
  if(arr[i] == target)
    return i;
}
return -1; 		Checks elements one by one from start to end.
In the worst case, every element must be compared.
Number of comparisons grows linearly with input size.
Best Case: O(1) (element at first position)
Worst Case: O(n) (element at last position or not present)
Binary Search

while(low <= high) {
  mid = (low + high) / 2;
  if(arr[mid] == target) return mid;
  else if(arr[mid] < target) low = mid + 1;
  else high = mid - 1;
} 		Works only on sorted arrays.
Each comparison removes half of the remaining elements.
Input size reduces as n → n/2 → n/4 → n/8.
Number of steps required is logarithmic.
Time Complexity: O(log n)

Linear Search performs comparisons sequentially, leading to linear time. Binary Search reduces the problem size in each step, resulting in logarithmic time.
