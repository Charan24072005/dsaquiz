⚙️ Sorting Algorithms

Sorting is the process of arranging elements in a specific order, usually ascending or descending. Sorting improves efficiency and is a fundamental concept in Data Structures and Algorithms.

Why Sorting is Important

  • Makes searching faster
  • Helps in ranking and ordering data
  • Used in many real-world applications
  • Frequently asked in interviews

Bubble Sort

Bubble Sort works by repeatedly comparing adjacent elements and swapping them if they are in the wrong order. After each complete pass through the array, the largest element moves to its correct position at the end. This process continues until the array becomes fully sorted. The algorithm is called “Bubble Sort” because larger elements gradually bubble up to the top of the list.

  • Best Case: O(n) – when the array is already sorted
  • Average Case: O(n²)
  • Worst Case: O(n²)
  • Stable: Yes

Selection Sort

Selection Sort divides the array into two parts: a sorted part and an unsorted part. In each iteration, it finds the smallest element from the unsorted portion and places it at the correct position in the sorted part. Even though it minimizes swaps, it still compares all remaining elements.

  • Best Case: O(n²)
  • Average Case: O(n²)
  • Worst Case: O(n²)
  • Stable: No

Insertion Sort

Insertion Sort builds the sorted array one element at a time. It takes the next element and inserts it into its correct position among the already sorted elements by shifting larger elements to the right. This is similar to how cards are sorted in hand.

  • Best Case: O(n) – when the array is already sorted
  • Average Case: O(n²)
  • Worst Case: O(n²)
  • Stable: Yes

Merge Sort

Merge Sort uses the divide and conquer technique. The array is repeatedly divided into smaller halves until each subarray contains only one element. These subarrays are then merged back together in a sorted manner to form the final sorted array. It guarantees consistent performance regardless of input order.

  • Best Case: O(n log n)
  • Average Case: O(n log n)
  • Worst Case: O(n log n)
  • Stable: Yes

Quick Sort

Quick Sort selects a pivot element and rearranges the array so that elements smaller than the pivot are placed before it and larger elements are placed after it. The same process is then applied recursively to both subarrays. It is very fast in practice but depends heavily on pivot selection.

  • Best Case: O(n log n)
  • Average Case: O(n log n)
  • Worst Case: O(n²) – when partitions are unbalanced
  • Stable: No

Heap Sort

Heap Sort first converts the array into a binary heap data structure. The largest element is repeatedly removed from the heap and placed at the end of the array while maintaining the heap property. This ensures predictable performance and does not depend on input order.

  • Best Case: O(n log n)
  • Average Case: O(n log n)
  • Worst Case: O(n log n)
  • Stable: No

Sorting Algorithms – Code & Time Complexity Calculation

The time complexity of sorting algorithms depends on how many comparisons and swaps are performed as the input size n increases.

Algorithm & Code How Time Complexity is Calculated
Bubble Sort

for(int i = 0; i < n; i++) {
  for(int j = 0; j < n-i-1; j++) {
    if(arr[j] > arr[j+1]) swap();
  }
} 		Two nested loops are used.
Outer loop runs n times.
Inner loop runs up to n times.
Total comparisons ≈ n × n = n².
Time Complexity: O(n²)
Selection Sort

for(int i = 0; i < n-1; i++) {
  min = i;
  for(int j = i+1; j < n; j++) {
    if(arr[j] < arr[min]) min = j;
  }
  swap(arr[i], arr[min]);
} 		For every element, the remaining array is scanned.
Number of comparisons ≈ n².
Even though swaps are few, comparisons dominate.
Time Complexity: O(n²)
Insertion Sort

for(int i = 1; i < n; i++) {
  key = arr[i];
  j = i - 1;
  while(j >= 0 && arr[j] > key) {
    arr[j+1] = arr[j];
    j--;
  }
  arr[j+1] = key;
} 		In worst case, each element is compared with all previous elements.
Nested shifting causes n² operations.
Best case (already sorted) runs in linear time.
Worst: O(n²), Best: O(n)
Merge Sort

mergeSort(arr) {
  divide array into halves
  mergeSort(left)
  mergeSort(right)
  merge(left, right)
} 		Array is divided into halves → log n levels.
At each level, merging takes O(n).
Total operations = n × log n.
Time Complexity: O(n log n)
Quick Sort

quickSort(arr) {
  pivot = choosePivot()
  partition array
  quickSort(left)
  quickSort(right)
} 		Partitioning divides array around pivot.
Average case gives balanced partitions → log n levels.
Worst case occurs with bad pivot choice.
Average: O(n log n), Worst: O(n²)

Sorting time complexity depends on how many comparisons and swaps are needed. Nested loops cause quadratic time, while divide-and-conquer approaches reduce complexity.
