💰 Greedy Algorithms

Greedy algorithms build a solution step by step by always choosing the option that looks best at the current moment. The goal is to reach an optimal solution using locally optimal decisions.

Why Greedy Algorithms are Important

  • Simple and efficient approach
  • Used in optimization problems
  • Faster than DP in many cases
  • Common in interviews

When Greedy Works

Greedy algorithms work correctly when a problem has:

  • Greedy choice property
  • Optimal substructure

Common Greedy Problems

Activity Selection Problem

Select the maximum number of activities that do not overlap by always choosing the activity that finishes first.

Fractional Knapsack

Select items based on value-to-weight ratio to maximize total value.

Coin Change (Greedy Version)

Use the largest denomination coins first to minimize the number of coins.

Minimum Platforms

Find the minimum number of platforms required so that no train waits.

Huffman Coding

Create optimal prefix codes using frequency-based merging.

Time Complexity

Greedy algorithms are usually fast and often involve sorting.

Greedy Algorithms – Code & Time Complexity

Greedy algorithms build the solution step by step by always choosing the locally optimal choice. Their correctness depends on the greedy choice property and optimal substructure.

Algorithm & Code Explanation & Time Complexity
Activity Selection Problem

sort activities by finish time
select first activity
for each next activity {
  if(start >= lastFinish) select activity;
} 		Always selects the activity that finishes earliest.
Sorting dominates the time complexity.
Single pass selection after sorting.
Time Complexity: O(n log n)
Fractional Knapsack

sort items by value/weight ratio
for each item {
  take full or fractional item;
} 		Chooses item with maximum value per unit weight.
Sorting by ratio dominates runtime.
Each item processed once.
Time Complexity: O(n log n)
Coin Change (Greedy)

sort coins in descending order
for each coin {
  while(amount >= coin) {
    take coin;
  }
} 		Always selects the largest denomination coin first.
Works correctly only for specific coin systems.
Linear scan after sorting.
Time Complexity: O(n log n)
Huffman Coding

create min heap of frequencies
while(heap size > 1) {
  extract two min nodes;
  merge and insert back;
} 		Greedily merges two least frequent characters.
Priority queue operations dominate runtime.
Heap operations repeated n times.
Time Complexity: O(n log n)
Minimum Platforms

sort arrival and departure times
use two pointers to track overlap
 		Greedily tracks maximum overlapping intervals.
Sorting dominates the process.
Single traversal after sorting.
Time Complexity: O(n log n)

Greedy algorithms are fast and simple but require proof of correctness. Choosing the wrong greedy strategy can lead to incorrect solutions.

Advantages of Greedy Algorithms

  • Easy to implement
  • Fast execution
  • Low memory usage

Disadvantages of Greedy Algorithms

  • Does not work for all problems
  • May fail if greedy choice is incorrect
  • Needs proof of correctness

Greedy vs Dynamic Programming

Greedy makes local choices, while DP explores all possibilities. DP guarantees correctness but greedy is often faster.

Greedy in Interviews

Interviewers expect you to explain why a greedy choice works. Always justify correctness with logic or proof.
